# 승인된 테스트 계정·임시 기록 삭제 결과 — 2026-10-22

## 승인과 범위

사용자는 보호할 본 계정을 제외하고, 앞서 특정한 신규 테스트 계정 A(ID 끝 `cdf0a7db`)와 임시 기록 2건의 영구 삭제를 승인했다. 이 승인은 다른 시험 계정이나 모든 비운영 계정을 일괄 삭제하는 승인으로 확대하지 않았다.

삭제 대상은 프로젝트 `frosty-term-80851719`의 `task7-account-deletion-test` (`br-steep-king-b38tirzy`)에만 존재했다. 운영 브랜치 `br-sweet-mountain-b3anx3dc`는 삭제에 사용하지 않았다. 대조군 B도 보존했다.

## 삭제 전 확인

- Neon 관리 API에서 테스트 브랜치가 ready이며 primary/default가 아님을 확인했다. 테스트 Auth endpoint는 `ep-ancient-darkness-b3ha58cs`로 운영과 다르다.
- 대상의 전체 UUID를 확인한 뒤, 이름과 이메일이 앞서 생성한 시험 계정 A의 조건에 일치하고 보호 계정 이메일과 다름을 확인했다. 실제 이메일·전체 UUID는 공개하지 않는다.
- 인증 사용자 1건, credential/login account 1건, 세션 1건.
- 자료 14개 테이블 중 날짜별 일지 1건과 가져오기 이력 1건. 나머지 12개 테이블은 0건.
- A를 제외한 자료 테이블 14개와 인증 user/account/session 테이블 3개의 건수 및 서버 측 상태 지문을 확보했다. 비밀값이나 개인 자료 본문을 반환하지 않고 집계/지문만 비교했다.

## 실제 수행 경로

Vercel 프로젝트 접근은 여전히 403이었다. Preview의 실제 환경변수 연결이나 브라우저 삭제 UI를 검증하지 못했으므로 해당 Preview를 통해 삭제하지 않았다.

1. **확인된 테스트 Neon 브랜치의 관리형 사용자 삭제 API**로 A 한 계정만 삭제했다.
2. 인증 사용자 제거를 확인하는 가드를 둔 SQL 트랜잭션으로 임시 기록만 정리했다. 계정별 advisory lock, `SET LOCAL ROLE pds_runtime`, A의 트랜잭션 한정 `app.user_id`를 사용했다.
3. 삭제 직전에도 일지 1건·가져오기 이력 1건 및 다른 대상 자료 0건인지 확인했다. 범위가 달랐다면 예외로 롤백하도록 했다.
4. 두 DELETE는 전체 대상 ID를 직접 조건으로 제한했다. 트랜잭션 안에서 14개 대상 테이블의 잔존 자료 0건도 확인했다.
5. 별도 후속 SELECT와 상태 지문 비교로 최종 상태를 재검증했다.

관리형 인증 삭제와 자료 삭제는 별개 호출이며, 이 정리가 완전한 분산 트랜잭션이었다고 주장하지 않는다. 이번에는 두 단계 모두 완료한 뒤 잔존 항목 0건을 확인했다.

## 확인하지 않은 것

- 이 결과는 **승인된 시험 계정 정리의 실제 성공**이다. PR #6의 `POST /api/account`나 브라우저 삭제 버튼으로 성공한 결과가 아니다.
- 관리형 자기 계정 삭제 `/delete-user`의 비밀번호 재확인 흐름이 실제 활성화됐다는 증거가 아니다. 관리형 디렉터리의 관리자 삭제 지원과 구분한다.
- 삭제 전 유효한 서명 쿠키와 원래 시험 비밀번호가 현재 실행 환경에 남아 있지 않아, 그 쿠키 재사용과 같은 자격증명 재로그인에 대한 삭제 전후 HTTP 대조는 수행하지 못했다.
- 읽기 전용 진단에서 DB 세션 토큰을 Bearer로 전달하는 시도는 삭제 전에도 인증되지 않았다. 이를 삭제 후 세션 차단 성공 증거로 사용하지 않았다. 진단용 임시 자격증명 파일은 제거했다.
- 세션 저장 행 1→0은 확인했지만, 원래 브라우저 쿠키 재사용의 HTTP 401을 실제 확인했다고 표시하지 않는다. 기존 자동 테스트의 stale-request 차단 및 거절/롤백 근거는 별도 검사다.
- 앱 계정 삭제 기능은 Vercel 접근과 자기 계정 삭제 흐름 검증이 남아 있으므로 Draft를 유지한다. C134의 기존 자료 처리 안내 대안 완료 판정은 그대로다.

실제 계정 이메일·비밀번호·전체 계정 ID·쿠키·토큰·해시·DB 비밀키는 이 문서에 게시하지 않는다. 이번 작업은 계정/자료 정리 및 증거 문서 갱신이며 애플리케이션 코드를 바꾸지 않았다.
