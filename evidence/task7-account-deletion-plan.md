# T07 — 계정·개인기록 삭제 안전 구현 (검증 대기)

> 이 브랜치는 **테스트 계정의 실제 삭제 전 코드 리뷰·모의 테스트 단계**입니다.
> 사용자 이메일·비밀번호·쿠키·토큰·세션 값은 소스/증거에 적지 않습니다.

## 구현 위치

- `api/account.js` — **GET** 삭제 대상 14개 컬렉션별 건수(본인 계정만) / **POST** 영구 삭제 절차. `user_id`는 요청 본문에서 받지 않고 관리형 인증이 확인한 계정 ID를 사용합니다.
- `api/auth.js` — 인증 서버의 내부 삭제 경로 `/delete-user`을 서버에서만 사용하도록 추가. 웹에서 직접 `/api/auth?action=deleteSelf` 호출 시 404를 반환하도록 차단.
- `index.html`, `account-deletion-ui.js` — 미리보기·백업 안내·이메일 재입력·비밀번호·`계정 삭제` 문구·재확인 대화상자. 비밀번호를 로그/저장소에 기록하지 않습니다.
- `tests/account-deletion.test.mjs` — 본인 계정 조건, 정확한 확인 정보 요구, 14개 테이블 대상, 인증 서비스 실패/보류 시 성공 취급 금지.
- `vercel.json` — 삭제 API 서버 함수 타임아웃 30초.

## 안전 조건

1. `ACCOUNT_DELETION_ENABLED`를 **`true`로 설정하지 않은 환경은 삭제 요청을 409로 거절**합니다. 공개 서비스에서 기본은 비활성입니다.
2. `GET /api/account` 미리보기는 서버에서 본인 세션을 확인하고 `asUser` + RLS 권한으로 각 컬렉션 건수만 조회합니다.
3. `POST`는 현재 인증 세션, 동일 출처, 본인 이메일 재입력, 비밀번호, 정확한 확인 문구를 요구합니다. 임의 사용자 ID를 직접 지정할 수 없습니다.
4. PostgreSQL 기록 삭제는 한 트랜잭션에서 본인 ID에만 적용합니다. 관리형 인증 삭제 결과가 `success:true, message:'User deleted'`인 경우에만 완료로 처리합니다. 이메일 확인만 보냈다는 응답은 성공이 아닙니다.
5. 관리형 인증이 `/delete-user` 기능을 활성화하지 않았거나 거절하면 **DB 삭제 트랜잭션을 롤백**합니다.
6. Auth와 SQL은 **서로 다른 시스템으로 완전한 원자적 트랜잭션이 불가능합니다.** Auth에서 계정을 지운 직후 DB 커밋에 실패하면 접근 불가능한 기록이 남을 수 있습니다. 이 경우 관리자 수동 조치가 필요합니다. 완료 여부가 애매할 때 다시 계정을 만들거나 자료를 임의 삭제하지 마세요.

## 실제 테스트 전 반드시 확인할 사항

- Neon Auth 운영 계정 삭제 엔드포인트의 실제 활성화 여부(관리형 설정에 따라 기본 비활성일 수 있음). 명시적으로 지원되지 않는다면 실삭제를 시도하지 않습니다.
- `ACCOUNT_DELETION_ENABLED`는 **별도 테스트 계정과 복구 가능한 자료로 검증된 후에만** 활성화합니다.
- 실제 삭제 대상 계정은 사용자가 지정한 **테스트 계정**으로만 제한하고, 사용자의 별도 최종 승인을 받은 뒤 해당 테스트 계정으로 직접 로그인하여 진행합니다.
- 삭제 전 개인 자료 건수, 성공 시 이전 세션 401, 삭제 후 본인 기록 0건, 다른 계정 건수 불변을 각각 마스킹한 증거로 기록합니다. 비밀번호/쿠키/세션은 제출하지 않습니다.
- 현재 이 브랜치의 코드는 모의 검증 단계입니다. **운영 계정 삭제의 성공을 주장하지 않습니다.**
