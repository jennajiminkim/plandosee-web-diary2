# T07 C105–C106 · C129–C131 — 제출용 추가 검증 기록

검사일: 2026-10-18 (Asia/Seoul). 공개 문서에는 실제 이메일, 비밀번호, 세션 쿠키, 토큰, 비밀키, 개인 자료 본문을 게시하지 않는다.

## 1. 증거 구분 및 범위

- **사용자 직접 확인(2026-10-18, Vercel 웹 UI):** `plandosee-web-diary2` Request Logs와 Runtime Logs를 구분해 최근 1시간(무료 Hobby 플랜에서 사용 가능한 범위) 확인. 검색 전 Request Logs에 `/api/auth`, `/api/state` 등의 실제 요청(HTTP 200 및 401)이 존재하는 캡처 확인.
- **사용자 직접 보고:** 검색어 `password`, `session_token=`, `authorization`, `cookie`, `DATABASE_URL`, `NEON_AUTH_COOKIE_SECRET` 각각 검색 결과 없음. 일부는 일반적인 단어 검색이므로 '결과 없음'은 선택한 로그 범위·검색 색인에 국한된다. **검색 결과별 화면 캡처는 보관되지 않았으며, 사용자 실측 보고임을 명시한다.**
- **사용자 직접 확인(Chrome Network → Response):** 로그인 실패 `/api/auth?action=login` 응답 본문에 `{"error":"이메일 또는 비밀번호를 확인해 주세요."}`만 표시. 캡처 원본에는 이메일 주소가 보이므로 **공개 GitHub에 업로드하지 않음**. 요청의 원본 Payload·Cookie·Authorization 헤더는 공개하지 않는다.
- **도구 한계:** Vercel 연결을 통한 24시간 Production Runtime Logs 조회는 **403 Forbidden**으로 실패. 이를 0건으로 계산하지 않는다.

## 2. C129 — 다섯 가지 대조 검사 (기존 실제 관찰 기록 사용)

아래 요청 형식의 `[REDACTED]`는 공개 설명을 위해 재구성한 마스킹 표기이며 **과거 HTTP 원본 덤프가 아니다**. HTTP 상태와 응답은 이전 사용자 실측에 근거한다. 성공·거절 쌍은 조건이 동일한 단일 반복실험이 아니라 각각의 기능·접근 경계를 보여 주는 대조이다.

| 검사 | 성공 요청 → 확인 결과 | 거절 요청 → 확인 결과 | 근거·제한 |
| --- | --- | --- | --- |
| ① 인증/로그아웃 | 로그인 중 `GET /api/state` → 본인 JSON 표시(정확한 HTTP 200 원본 캡처 없음) | 로그아웃 후 **동일** `GET /api/state` → **401** `{"error":"authentication_required"}` | `task7-auth-verification.md` 1절 |
| ② 과거 세션 재사용 | 로그인 중 `GET /api/state` → 본인 자료 반환 | 로그아웃 전에 보관했던 `session_token=[REDACTED]` 쿠키를 재전송한 `GET /api/state` → **401** | 쿠키 값 원문은 보관·게시하지 않음; 2절 |
| ③ 계정별 조회 제한 | 계정 A 본인 기록 조회 → **200**, `verified:true` | A 세션의 `GET /api/ownership-test?id=[B_RECORD_ID]` → **404** `{"error":"not_found"}` (반대 방향 B→A도 404) | 원본 전체 헤더/본문 미보존; 3절 |
| ④ 계정별 수정 제한 | A 본인 테스트 계획 목록 `GET /api/ownership-test` → **200**, A 소유 자료만 | A의 `PATCH /api/ownership-test` 본문 `{"id":"[B_RECORD_ID]"}` → **404** (B→A도 404) | 이 행의 성공·거절은 **서로 다른 메서드**; PATCH 성공을 실측했다고 주장하지 않음. DB 전후 상태 불변 확인; 3·10절 |
| ⑤ 계정별 삭제 제한 | B 본인 테스트 계획 목록 `GET /api/ownership-test` → **200**, B 소유 자료만 | B의 `DELETE /api/ownership-test` 본문 `{"id":"[A_RECORD_ID]"}` → **404** (A→B도 404) | 이 행의 성공·거절은 **서로 다른 메서드**; DELETE 성공을 실측했다고 주장하지 않음. DB 전후 상태 불변 확인; 3·10절 |

추가 확인된 별도 HTTP 결과: 기존 이메일 중복 가입 **400**, 기존 이메일+잘못된 비밀번호 **401**, 없는 이메일+잘못된 비밀번호 **401**, 후자의 오류 문구는 서로 동일(기존 증거 문서 7절). 계정 목록 구분(8절), URL·헤더·본문 사용자 ID 변조에도 세션 소유 계정으로만 처리(9절), 양방향 PATCH/DELETE 404 이후 건수·지문 불변(10절)을 참고한다.

**C129 판정:** 5개 대조 항목의 HTTP 관찰 및 접근 제한을 증거에 연결해 **제출용 요약 보완 완료**. 원본 요청·응답의 전체 헤더/본문이 당시 보관되지 않은 사례가 있으므로 '완전한 원본 HTTP 다섯 쌍 확보'라고 주장하지 않는다.

## 3. C105·C106 — 비밀번호 유출 관련 점검

- `api/auth.js`: 인증 실패 응답은 일반 오류 메시지로 치환하며, 서버 예외 기록에 자격증명·쿠키·상위 응답 payload를 직접 출력하지 않는다.
- `api/db.js`: DB 접속 문자열은 서버 환경변수에서 읽는다.
- `api/state.js`: 실패 응답은 정형화된 상태/오류를 반환하며, 예상치 못한 오류 로그에 요청 본문을 인쇄하지 않는다.
- **2026-10-18 로그인 실패 응답 실측:** `{"error":"이메일 또는 비밀번호를 확인해 주세요."}`. 해당 응답 본문에서 비밀번호·토큰·비밀키 원문 미발견.
- 로그인 **요청 Payload에는 인증을 위한 비밀번호가 전송된다**. 이는 TLS 보호되는 요청이며, 요청 비밀번호가 '전송되지 않는다'고 주장하지 않는다. C105·C106의 로그/응답 노출 여부와 구분한다.
- Vercel 로그 사용자 확인: 최근 1시간, 위 6개 문자열 미발견. 검색 화면 전체/기간 외 로그/모든 응답/브라우저 모든 화면의 전수 증명이 아니다.

**판정:** C105는 현재 확보된 요청·응답과 로그 범위에서 **통과 근거 보강**. C106은 검사한 로그인 실패 응답 및 로그에서는 비밀정보 원문 미노출, 다만 '어디에도 없음'의 전수 검증은 미완료.

## 4. C130 — 아직 못 막은 것과 위험

- **무차별 대입 대응 정책 미확인:** 관리형 Neon Auth의 운영 속도 제한/계정 잠금을 검증하지 못하여 반복 비밀번호 추측에 노출될 가능성이 있다.
- **계정 삭제 흐름 미완성:** 인증 계정과 별도 다이어리 데이터가 함께 삭제되는지 검증되지 않아 개인정보가 남을 수 있다.
- **전체 로그/화면 전수 미검증:** 무료 플랜 조회 범위 외의 과거 로그와 다른 응답 경로에서 비밀값 노출 여부를 확정할 수 없다.

## 5. C131 — 비밀값 원문 노출 방지

- 이 문서에는 비밀번호 원문, 실제 세션/토큰, 쿠키값, 개인 이메일, 실제 해시 및 서버 비밀키 값을 기재하지 않았다.
- 기존 공개 증거 문서 역시 `[REDACTED]`와 기록 종류/건수/응답 상태만 사용한다.
- 과거 GitHub 브랜치·커밋에서 고신뢰 비밀정보 패턴 0건이라는 **기존 검사 결과**는 `task7-secret-history-hash-and-http-audit.md`에 기록되어 있다. 이는 모든 형식과 외부 플랫폼을 전수 보장하지 않는다.
- **C131 판정:** 본 추가 제출 문서의 비밀정보 원문 없음. 과제 제출물 *전체*에 대한 지속적인 비밀정보 감사는 별도 필요.
