# T07-C111 / C114 — 세션 만료·비밀번호 변경 후 세션 무효화 검증 (2026-10-18)

> 상태: **운영 데이터 읽기 전용 점검 + 서버 코드 모의 검증 통과 / 실제 만료·비밀번호 변경 실측 대기.**
> 사용자의 계정 비밀번호·실제 세션·Neon 운영 자료에 대한 변경은 아직 진행하지 않았습니다.

## A. 세션 만료(T07-C111) — 운영 데이터 읽기 전용 점검

Neon 관리형 Auth가 연결된 운영 production branch에서 세션 토큰·계정 이메일·IP·접속 기록 원문을 조회하지 않고, `neon_auth.session` 전체에 대한 **집계만** 읽었습니다.

| 항목 | 2026-10-18 점검 결과 |
| --- | --- |
| 세션 수 | **14건** |
| 만료 전 세션 | **14건** |
| 이미 만료된 세션 | **0건** |
| 생성~만료 시각 차이 | 최소·최대 **168시간(7일)** |
| 세션이 있는 사용자 수 | **4명** |

**증명 범위:** 7일 초기 만료 시각 저장 실측. 사용 시 갱신 가능성, 이미 만료된 쿠키 실제 재전송 401은 확인하지 못했습니다.

**만료 시 서버 차단 모의 테스트:** 현재 브랜치의 `tests/task7-session-expiration.test.mjs`가 `api/db.js`의 실제 `requireUser`와 `api/state.js`의 실제 핸들러를 추출해 실행합니다. Neon 인증 서버가 만료 또는 무효 세션을 거절하도록 합성한 조건에서 **HTTP 401 + 개인 DB 읽기 0회** 등 **5/5 통과**. 이는 실제 만료 쿠키의 운영 응답이 아닙니다.

Better Auth 기본 정책은 `expiresIn=7일`, `updateAge=1일`이며 세션 이용 시 만료가 연장될 수 있습니다. 서비스가 실제로 선택한 정책은 관리형 Auth 운영 설정과 사용자 요청 이력에 따라 달라질 수 있습니다.

공식 참고: https://better-auth.com/docs/concepts/session-management

## B. 비밀번호 변경 후 타 세션 무효화(T07-C114) — 변경 없는 준비

Better Auth 공식 API: `POST /change-password`, 요청 필드 `currentPassword`, `newPassword`, `revokeOtherSessions:true`. **현재 작업을 수행하는 세션은 유지하고 다른 세션들을 폐기하도록 요청**하는 기능입니다. 출처: https://better-auth.com/docs/concepts/users-accounts

기존 운영 `main`에는 비밀번호 변경용 프록시가 없으므로 **별도 브랜치**에 아래 작업만 준비했습니다.

- `api/auth.js`: `/api/auth?action=changePassword`를 Neon 관리형 Auth에 중계. `PASSWORD_CHANGE_TEST_ENABLED=true` 및 `PASSWORD_CHANGE_TEST_USER_ID`가 **모두** 일치해야 작동하며 기본값은 **404 비활성화**입니다. 로그인 세션 필수·Origin 검증·비밀번호 길이 8~128자·동일 비밀번호 차단·`revokeOtherSessions:true` 서버 강제·비밀 출력 금지·공통 오류 응답.
- `password-session-test.html` + `password-session-test-ui.js`: 사용자가 실제 비밀번호를 채팅/Console에 올리지 않고, 브라우저 비밀번호 입력칸에 직접 넣는 테스트 전용 UI. 초기에는 세션 확인 전 폼 숨김. 계정 허용 목록이 있어도 **사용자 최종 승인 전 실제 변경은 진행하지 않음**.
- `tests/task7-password-revocation.test.mjs`: 차단 기본값·위조 Origin·미인증·비밀번호 입력 오류·서버 사용자 허용 목록·폐기 플래그·민감정보 응답 미노출·에러 처리 등 **9/9 모의 통과**.
- 두 검증 파일을 합쳐 **14/14 모의 통과** (V8에서 함수 소스 호출 + 가짜 Request/Response/Neon 응답; 실제 Neon 호출/실제 Node 배포 빌드는 아직 하지 않음).

### 실측 전에 필요한 분명한 승인 및 안전 절차

1. **승인:** 사용자에게 별도 시험용 계정(기존 중요한 다이어리 계정 제외)으로 비밀번호를 실제 변경하고, 해당 계정의 **다른 브라우저 세션을 무효화하는 작업**을 진행할지 확인합니다. 계정이나 비밀번호 원문을 채팅에 입력받지 않습니다.
2. **배포 전 확인:** GitHub 별도 브랜치 테스트를 검토하고 Vercel **Preview만** 배포. `PASSWORD_CHANGE_TEST_ENABLED=true` 및 `PASSWORD_CHANGE_TEST_USER_ID`는 Preview의 테스트 계정에만 적용; 운영 Production에 활성화하지 않습니다. 계정 식별자는 환경변수로 관리하며 공개 저장소에 쓰지 않습니다.
3. **동일 시험 계정으로 두 창 로그인:** A (비밀번호 변경을 실행할 창), B (검사할 다른 세션). 성공 전 B의 `GET /api/state`는 200인 상태 확인.
4. **A에서 변경:** 시험용 UI에 기존/새 비밀번호를 직접 입력해 실행. Provider가 지원하여 성공 응답한 경우에만 다음으로 진행합니다. **Neon 관리형 Auth의 이 동작은 아직 실제 확인되지 않음**.
5. **B에서 검증:** 같은 시험 계정이지만 별도 B 세션으로 `GET /api/state`를 호출하여 **HTTP 401**인지 확인, A는 자기 세션 유지가 예상됨. DB 읽기 전용으로 시험 계정 세션의 활성 건수 변화 확인 가능.
6. **마무리:** 새 비밀번호로 해당 시험 계정 재로그인. 비밀번호를 이전 값으로 복원하려면 **별도의 변경 요청과 사전 동의**가 필요합니다. 자동 복원이나 계정 삭제는 하지 않습니다.

**세션 자연 만료 실측:** 현재 만료된 세션이 없으므로 통과 판정 불가. 실제 운영 DB의 세션 만료 시각을 인위적으로 변경하는 방식은 **현재 허가되지 않았고 수행하지 않았습니다**. 세션 갱신되지 않는 시험 세션을 두고 만료 후 확인하려면 별도의 시간 경과가 필요합니다.

- 실배포 Preview 환경에서 서버 핸들러 정상 호출/브라우저 입력 폼 작동 여부.

**개인정보·보안:** 사용자 이메일·비밀번호·토큰·쿠키·DB 접속 정보·개인 다이어리 내용은 기록하지 않았습니다. GitHub `main`이나 운영 Vercel Production을 변경하지 않았습니다.
