# T07 — 배포 없이 진행한 미완료 인증 검증 (2026-10-18)

> 이 문서는 기존에 **실측 통과한** 로그아웃 쿠키 재사용 401, A↔B 읽기/수정/삭제 404 6건, 암호 해시·솔트, 개인 JSON 다운로드 검사를 재실행하지 않습니다.
> 공개 저장소에 이메일·비밀번호·쿠키·세션·원본 자료 본문을 넣지 않습니다.

## 2. 현재 소스에서 별도 확인한 방어 위치

- `api/auth.js`: 관리형 인증 실패 시 두 로그인 상황 모두 `401 {"error":"이메일 또는 비밀번호를 확인해 주세요."}`로 통일, 응답 JSON에 비밀번호 원문 재전송 안 함.
- `api/db.js`: `requireUser`가 관리형 인증에서 계정 ID 획득; `asUser`가 SQL 트랜잭션 내부에서 `pds_runtime` 역할과 `app.user_id` 설정.
- `api/state.js`: 전역 사용자 목록이 아니라 `WHERE user_id=$1`인 본인 데이터 목록.
- `api/ownership-test.js`: 전용 검사 계획의 읽기/목록/수정/삭제 쿼리마다 인증한 `userId`가 SQL 조건으로 적용. 브라우저의 `user_id` 값으로 현재 로그인한 주인을 변경하지 않음.
- `neon/001_diary_schema.sql`: 개인 기록 테이블마다 `ENABLE ROW LEVEL SECURITY` 및 `FORCE ROW LEVEL SECURITY` 설정 코드 존재.
- 비밀번호를 네트워크 **요청** 본문에 담는 것은 로그인 동작 자체에 필요한 것이므로 C105/106의 요건은 원문을 제출 증거/응답/로그로 유출하지 않는지에 대한 확인입니다. **개발자도구 Network의 Request Payload에는 사용자 본인 비밀번호가 보일 수 있습니다. 절대 캡처·공유하지 마세요.**

## 3. 실제 브라우저 실측이 필요한 최소 항목 (배포 불필요)

아래는 **검사 안내**이며 실행 결과가 아닙니다. 사용하는 계정의 실제 비밀번호를 제출하거나 채팅에 붙여넣지 않습니다.

### A. C98 중복 가입, C99 두 로그인 실패 안내

1. 새 시크릿 창에서 [운영 사이트](https://plandosee-web-diary2.vercel.app/)에 접속합니다.
2. **중복 가입:** 이미 가입한 테스트 계정 이메일로 가입 시도 시 별도 두 번째 계정이 생성되지 않는지 확인합니다. 비밀번호는 사용자 브라우저에만 입력합니다.
3. **실패 안내:** 존재하지 않는 가상의 이메일과 틀린 비밀번호, 기존 테스트 계정 이메일과 틀린 비밀번호를 각각 한 번씩 로그인 시도. **실제 HTTP 상태와 화면에 표시된 동일 문구만** 기록합니다. 과도한 로그인 시도 금지.
4. 증거는 `요청: POST /api/auth?action=login, 비밀번호=[비공개]`처럼 기록합니다. Network `Payload`의 비밀번호·쿠키가 보이는 캡처는 게시하지 않습니다.

### B. C125 목록 분리 및 C122 실측 건수

1. [기존 계정 격리 검사 화면](https://plandosee-web-diary2.vercel.app/isolation-test.html)에 A 계정으로 로그인하여 **내 테스트 목록 조회**. 기록 ID 원문은 게시하지 않고 **A 본인 목록 건수**만 기록.
2. 같은 화면에서 B 계정으로 로그인하여 B 본인 목록 건수만 기록. 각자 타인 자료가 섞이지 않았는지 확인. 양방향 404 검사는 이미 완료됐으므로 다시 하지 않습니다.
3. C122는 과거 교차 수정/삭제 실측 **직전·직후 건수 자료가 없으면** 완전한 실측 근거가 되지 않습니다. 재실행을 하지 않으려면 당시 저장한 스크린샷/로그를 찾아 증거에 첨부하세요. 없으면 "모의 불변 검사 PASS / 당시 실측 건수 자료 없음"이라고 제출합니다.

### C. C123 실제 변조 요청

실제 HTTP 수준에서 `user_id=B`를 URL·헤더·본문에 넣은 요청은 별도 증거가 필요합니다. 코드 모의 검사는 통과했으나 현재 `isolation-test.html`은 사용자 지정 헤더나 임의 `user_id` 필드 추가 UI를 제공하지 않습니다. 무리하게 개발자도구에서 쿠키·비밀번호가 포함된 요청 전체를 공유하지 말고, 서버 변조 검사를 수행할 수 있는 테스트 도구를 추가한 뒤 시행하는 방법도 가능합니다.

## 4. 계속 미완료인 다른 항목

- C98 중복 이메일 실제 서버 거절, C99 서로 다른 로그인 실패의 실제 HTTP 비교.
- C103 실제 저장 비밀번호 예시의 **안전하게 가린** 제시 방식, C105~106 서버 로그 및 응답 본문 점검.
- C111 세션 TTL **현재 Neon Auth 운영 설정**; C114 비밀번호 변경 후 기존 세션 폐기.
- C01/C03 새 시크릿 창 로그인 첫 화면 캡처.
- C122/C123/C125 실측 증거 및 C129 성공·거절 쌍 완성.
- C134 계정/데이터 연계 삭제: 별도 [Draft PR #6](https://github.com/jennajiminkim/plandosee-web-diary2/pull/6)에서 실제 삭제 기능 검증 대기.

**주의:** 현 단계에서는 개인 기록·계정·데이터베이스 내용을 변경하지 않았습니다. 사용자에게 완료되지 않은 항목을 "실측 통과"라고 보고하지 않습니다.
